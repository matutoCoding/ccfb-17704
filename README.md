# 雪场公园设计与腾空推演系统

浏览器里的地形公园设计、压雪施工与腾空轨迹推演工具。TypeScript + Three.js + 自写雪面 Shader，方案存 IndexedDB。

## 运行

```bash
npm install
npm run dev        # http://127.0.0.1:5188
npm test           # 46 个单元/精度测试（Vitest）
npm run build      # 类型检查 + 生产构建到 dist/
```

## 六个页面

1. **雪道地形**：201×141 高程网格（400×280m 测试雪场）；支持 JSON 高程网格、CSV 矩阵、等高线（IDW 插值）导入与 JSON 导出；雪厚是独立图层，热力图让薄雪/露石区一眼可见；Marching Squares 等高线叠加。
2. **道具库**：S/M/L 跳台、两种箱子、平杆/下坡杆、U 型池、6/10 级台阶，全部参数化（起跳角、台高、平台长、落地坡角/坡长、缓冲区、宽度等）。
3. **公园布置**：点击放置、直接拖动（射线贴地）、朝向/XYZ/全部参数编辑、顺序调整；自动做入台速度窗口、道具间距、制动距离与速度链校核。
4. **压雪施工**：在雪道上点选推铲轨迹，按铲宽/分层切深“推一层”；逐格算挖方、填方、内部倒运、推至末端集雪堆、外借雪；橙/蓝球与箭头给出“雪从哪来、运到哪去”，支持逐层记录与恢复原始雪面。
5. **腾空推演**：抛体 + 二次空气阻力的 RK4 数值解，步内连续碰撞（12 子步扫描 + 32 次二分求最早交点），落点判定到平台/落地坡/缓冲区；不在落地坡上整段标红；输出滞空、距离、落地姿态、法向冲击、**等效落高 EFH = v_n²/(2g)**、垂直落差；可第一人称沿轨迹回放（播放/暂停/进度/倍速）。页内有“落点精度自检”。
6. **方案对比**：任意两版 IndexedDB 方案对比总雪量、挖填/调运、红/警安全项、最大 EFH、是否全部落在落地坡，带条形图与问题清单。

## 物理精度（最在意的指标）

- 生产求解器：RK4，`dt=1/240s`，落地根用二分精修。
- 参考解：RK4 `dt=1/6000s`。
- `src/core/physics.test.ts`：
  - 无阻力时与解析射程 `v²sin2θ/g` 误差 < 2cm；
  - **500 个随机案例（速度/起跳角/阻力系数/落地坡）生产解 vs 高精度参考解，最大落点误差约 5×10⁻¹² m**，远小于 0.2m 预算；
  - 示例方案断言：A 版有一个短落地坡跳台冲出落地坡（红），B 版加长后全部落回落地坡且无红项。

## 速度链与雪面摩擦

雪况摩擦系数：软雪 μ=0.10、硬雪 μ=0.045、冰面 μ=0.018。速度按弧长积分
`du/dl = 2(-g·sinθ - μ·g·cosθ - k·u)`（u=v²，含空气阻力 k≈0.0041/m），
滑手会主动搓雪把速度控制到下一道具建议区间；落地只保留沿坡切向速度。
间距校核使用主动刹车摩擦（冰面明显更低），陡坡冰面上可能判定“无法在间距内减速”。

## 雪面 Shader

`src/three/snowMaterial.ts` 全手写：

- 压雪车作业后写入 RGBA 方向掩码 DataTexture，雪面按掩码生成定向**灯芯绒纹**（法线扰动 + 刻槽明暗，远距离淡出防摩尔纹）；
- 太阳视角对齐的哈希**雪晶闪光**；
- 晴天强侧光 / **阴天平光**（压暗太阳、抬高环境、加白雾），平光下起伏难以辨认；
- 雪厚热力图与距离雾。

## 性能

整个公园约 **5.8 万三角面 / 40 个 draw call**；像素比上限 1.75，连续 3 个采样窗口低于 45fps 自动降分辨率（最低 0.8 DPR），高于 57fps 缓慢回升。主流独显/核显在 1080p 下可达 45fps+。
（仓库内 Playwright 冒烟在 SwiftShader 软件渲染下仅 20–25fps，不代表真实 GPU。）

## 测试数据

内置两版方案并在首次打开时写入 IndexedDB：

- **方案 A · 初版（落点不足）**：小雪台、箱子、铁杆、一个落地坡仅 4m 的中型跳台（速度到位后冲出落地坡，EFH 超标，标红）、台阶、U 型池；地形含两处薄雪/露石斑与两条推铲记录。
- **方案 B · 修订**：把该落地坡加长到 20m、加陡 3°，其余不变，落点回到坡中央，全场无红项；另有补雪线与更多碾压层。
